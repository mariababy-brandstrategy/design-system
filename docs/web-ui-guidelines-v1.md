마리아의료재단 **사내 웹 서비스**(로그인 뒤 직원이 쓰는 도구)를 만들 때 따라야 하는 단일 기준.
신규 앱은 **이 문서에서 시작**한다.

레퍼런스 구현: **console**(console.maria-baby.com) · **popo-studio**(popo-studio.maria-baby.com) · **mou-admin**(mou-admin.maria-baby.com). (v1 추출 당시의 4앱 중 **claim 은 2026-08-22 앱 폐기** — 아래 본문의 claim 언급은 실측 당시의 이력 기록이다.)

> **이 repo(design-system)가 단일 출처(SoT)다.** 토큰값은 `tokens/design-tokens.css`, 헤더는 `docs/internal-service-header-v1.md`, 전체 규칙은 본 문서.
> 코드 부품(토큰·컴포넌트)을 앱에 **설치**하는 건 shadcn 레지스트리 **`@maria`**(github `dyshin-maria/maria-ui`, https://maria-ui.vercel.app)가 담당 — 레지스트리는 이 repo의 토큰을 *복제*할 뿐, 값이 갈리면 **이 repo가 우선**이다.

## 1-1. 로고 (브랜드 워드마크)

마리아 로고는 **전용 워드마크**(커스텀 BI — `R`자에 사람 모티프가 든 디자인)다. **어떤 폰트로도 글자를 타이핑해 흉내 내지 말 것.** 반드시 아래 벡터 자산을 쓴다.

- **정본 자산**: `assets/logos/svg/`
  - `maria-wordmark.svg` — `fill="currentColor"`. 인라인 SVG·React에서 색을 CSS로 제어(**권장**).
  - `maria-wordmark-green.svg` — 고정 마리아 그린 `#1E3131`. 밝은 배경·`<img>`용.
  - `maria-wordmark-white.svg` — 고정 흰색. 어두운 배경·`<img>`용.
  - 래스터가 필요하면 `assets/logos/*.png`(white·색상별 01~05).
- **색 규칙**: 어두운 배경 = **흰색**, 밝은 배경 = **마리아 그린 `#1E3131`**(디자이너 3원칙 "어두운 배경엔 100% white"와 일치). **아이보리 워드마크 금지.**
- **비율·여백**: 601:229 (≈2.63:1) 고정, 가로세로비 유지. 클리어 스페이스 = 워드마크 높이의 1/2 이상.
- **코드 소비**: `@maria/brand-logo`(registry:component, currentColor 인라인) → 어두운 배경 `<BrandLogo className="h-5 text-white" />`, 밝은 배경 `text-maria-green`. 비-React/정적 HTML은 위 SVG를 인라인하거나 `<img src="…maria-wordmark-{green|white}.svg">`.
- **텍스트와 나란히 둘 때**: 원본 viewBox 는 `.ai` 페이지 박스라 마크 **아래에 52.4/228.8 만큼 여백**이 남는다. 그대로 가운데 정렬하면 옆 글자와 **밑선이 어긋난다**(2026-07-31 헤더에서 발견). `trim` 속성(마크 실제 경계 viewBox `52.586 27.125 496.027 149.266`) + `items-baseline` 을 쓴다 — 상자 밑변이 곧 글자 밑선이라 폰트 지표와 무관하게 맞는다.
- **출처/재생성**: `01.로고/로고모음/로고 색상별.ai` → `pdftocairo -svg -f1 -l1`(벡터, 래스터 내장 0). .ai 원본 그린(#163231)은 공식 토큰 #1E3131로 정규화.
- **현재 적용 현황(2026-08-04)**: 정적 산출물·신규 작업 + **사내 웹앱 헤더 6/6** 워드마크 사용(console·popo·mou·claim·hub·labs 전수 — `internal-service-header-v1.md` §8 참조. labs 는 운영자 영역 한정 헤더). 텍스트 로고 legacy 허용은 **종료** — ui-audit static 이 `header-wordmark` 로 강제한다(BrandLogo 부재 또는 아이보리 착색이면 FAIL). hub 도 ui-audit APPS 에 등록돼 같은 강제를 받는다. 헤더 적용 규격은 `internal-service-header-v1.md` §2·§4(v1.9).

## 1-2. 아이콘 (v1.12, 2026-08-21 신설)

아이콘 정본은 **Lucide 계열 한 세트**다. 2026-08-21 실측 전까지 정본이 정해진 적이 없었다 —
claim(웹·desktop)만 lucide 를 쓰고 console·hub·popo-studio·mou·labs 는 필요할 때마다
인라인 `<svg>` 를 손으로 그려 넣고 있었다. 이 절은 그 상태를 끝내기 위한 것이다.
**이미 사실상의 기본값이던 것을 문서로 굳히는 것**이라 이동 비용은 거의 없다.

> 이 절이 정하는 것은 **눈에 보이는 약속**(어느 계열·크기·획·색·접근성)뿐이다.
> 구현 매핑(npm 패키지명 `lucide-react`·지원 버전 범위·설치법)은 배포층인
> **maria-ui `registry.json` 의 `@maria/icon` 항목이 단일 출처**다. 같은 값을 두 곳에 적지 않는다.

### 규칙

- **세트 — Lucide 계열만.** **두 번째 아이콘 세트를 들이지 않는다.** 세트마다 획 굵기·광학 크기·
  모서리 처리가 달라 한 화면에 섞이면 바로 보인다. 필요한 글리프가 Lucide 에 없으면
  인라인 `<svg>` 를 그리기 전에 **§8 예외 절차**(사전 확인 후 이 문서에 기록)를 밟는다.
  → 자동 검사 `icon-set(static)` 이 **알려진** 대체 세트를 잡는다(아래 "검사의 한계" 참조).
- **격자·획 — 24×24, `stroke-width` 2**(Lucide 기본값). `strokeWidth` 를 재정의하지 않는다.
  (7앱 실측 재정의 **0건** — 이미 지켜지던 것을 명문화한 것이다.)
- **색 — `currentColor` 를 그대로 두고 글자 색 유틸(`text-*`)로 제어**한다. 아이콘에 색을 직접
  박지 않는다. 부모의 글자 색을 따라가는 것이 기본 동작이고, 그래야 다크·반전 표면에서 같이 움직인다.
- **크기 — 숫자가 아니라 역할로 고른다.**

  | 역할 | 크기 | 클래스 | 쓰는 곳 |
  |---|---|---|---|
  | 인라인 | 14px | `size-3.5` | 본문 글자 옆, 배지·칩 안 |
  | **기본** | 16px | **`size-4`** | 버튼·입력·셀렉트·메뉴 항목 — **애매하면 이것** |
  | 강조 | 20px | `size-5` | 카드 머리말, 목록 항목의 선행 아이콘 |
  | 전체 화면 상태 | 32·48px | `size-8`·`size-12` | 페이지 전체 로딩 스피너, 빈 화면 |

  **크기 목록만 적으면 난립이 그대로 재발하므로 역할을 함께 못박는다** — 실측 당시 claim 웹이
  18회 사용에 7가지 크기, desktop 이 18회에 7가지를 쓰고 있었다.
  표 밖의 크기는 **§8 예외**(사전 확인 후 기록)다.
- **표기는 `size-*` 하나로.** `h-4 w-4` 는 결과가 같지만 표기가 갈리면 검색·감사가 성립하지 않는다.
  ⚠ 이 규칙은 **아이콘 컴포넌트에만** 적용된다 — §3 `AuthOtpHelp` 의 `h-4 w-4` 는 아이콘이 아니라
  `?` 글자를 담은 **버튼**의 크기라 대상이 아니다.
- **import 이름은 짧은 쪽.** `Check`·`Search` 를 쓰고 `CheckIcon`·`SearchIcon` 별칭은 쓰지 않는다
  (같은 글리프에 이름이 둘이면 검색·감사가 반쪽이 된다).
- **위 두 항목의 공통 예외 = `components/ui/` 의 shadcn 생성 파일.** CLI 가 다시 만들어내는 파일이라
  손으로 고치지 않는다(고쳐도 다음 `shadcn add` 에 덮인다). 실측상 `*Icon` 별칭은 정확히 이 디렉터리
  6개 파일에만 있고, 손으로 쓴 19개 파일은 전부 짧은 이름을 쓰고 있었다.
- **접근성** — 크기·획·색만 정하면 정본이 반쪽이다.
  - **장식용**(옆에 같은 뜻의 글자가 이미 있음) → `aria-hidden`.
  - **아이콘이 혼자 뜻을 전달**하면 → 접근 가능한 이름을 준다(옆에 텍스트를 두거나 `aria-label`).
  - **아이콘만 있는 버튼은 `aria-label` 필수.** 없으면 스크린리더에서 "버튼"으로만 읽힌다.

### 검사의 한계 (정직 표기)

`icon-set(static)` 은 **알려진** 대체 아이콘 패키지(tabler·hugeicons·heroicons·react-icons 등)를
FAIL 로 잡고, 이름이 수상한 미지 패키지는 **WARN + 사람 판정**으로 돌린다.
**"아이콘 패키지인가"의 판정은 결국 사람의 의미 판단이라 완전한 자동 차단은 불가능하다.**
검사 이름에 `known-` 을 붙여 이 불완전성을 드러냈고, 못 잡는 구간은 §8 사전 확인 게이트가 막는다.

### 미수렴 (2026-08-21 현재)

- **claim 12px 6곳**(웹 3 + desktop 3, `audit-results-view.tsx` 의 `h-3 w-3`) — 역할 표 밖 크기.
- **console·hub·popo-studio·mou·labs 의 인라인 `<svg>`** — 아이콘 패키지 없이 손으로 그린 것.
- 둘 다 **각 앱을 다음에 손볼 때 수렴**한다(사용자 결정 2026-08-21 — 일괄 교체하지 않는다).
  정본 수립이 먼저이고 수렴은 자연히 따라온다는 판단이다.

## 1-3. 브라우저 탭 제목 (v1.13, 2026-08-21 신설)

탭 제목 정본은 **`{가장 구체적인 것} · {앱 이름}`** 이다.

계기는 실사용 보고다 — 같은 앱 창을 여러 개 띄우면 **탭이 전부 "마리아 SNS"로 보여 구분이
안 됐다**(스크린샷 근거, 탭 5개 전부 동일). 원인은 두 겹이었다.

1. **페이지별 제목이 없다.** 2026-08-21 실측: hub 28/30, mou 4/13, **labs 0/10 · claim 0/19 ·
   sns 0/10 · console 0/? · popo 0/?**. 제목이 없으면 전 페이지가 루트 제목 하나를 공유한다.
2. **모든 제목이 같은 접두로 시작한다.** "마리아 분원 허브"·"마리아 통합 콘솔"·"마리아 SNS 콘텐츠"는
   앞 세 글자가 같다. 탭이 좁아지면 뒤가 잘리므로, 구체적인 것이 뒤에 있으면 잘려서 안 보인다.

> ⚠ **"탭에 N자가 보인다"를 규칙의 근거로 쓰지 않는다.** 크롬은 글자 수가 아니라 폭(DIP)으로
> 자르고 버전·기기·창 상태·탭 수에 따라 달라진다. 이 절의 근거는 **"뒤가 잘려도 앞의 구체명이
> 남는다"는 순서**뿐이다. 관찰값을 계약으로 굳히면 크롬이 바뀔 때 조용히 깨진다.

> 이 절이 정하는 것은 **눈에 보이는 약속**(무엇을 어떤 순서로·무슨 구분자로)이다.
> 구현(정규화 함수·길이 상한 상수·Next 조립 방식)은 각 앱의 `lib/document-title.ts` 가 담당하고,
> **레퍼런스 구현 = sns `src/lib/document-title.ts`**(2026-08-21 파일럿).

### 규칙

- **형식**
  - 사내 도구 — `{페이지·콘텐츠} · {앱 이름}` (예: `상황판 · 마리아 SNS 콘텐츠`)
  - 대외 공개 — `{페이지} · {서비스명} · 마리아의료재단` (예: `진료 접수 · MOU · 마리아의료재단`)
  - 기관명은 **대외 경로에만** 붙인다. 사내 도구는 로그인한 직원만 보고, 전 앱 파비콘이 같아
    브랜드는 이미 전달된다. 불일치가 아니라 "공통 핵심 + 대상별 확장"이다.
- **구분자는 ` · `(가운뎃점) 하나.** hub 가 이미 쓰던 표기를 승격했다. `|`·`-`·`—` 를 섞지 않는다.
  접근성·검색 표준은 특정 구분자를 요구하지 않으므로(스크린리더의 문장부호 낭독은 제품·설정마다
  다르다) **구분자에 의미를 맡기지 않고 표기 통일만 취한다.**
- **의미가 다른 화면은 반드시 고유 제목을 갖는다.** 순서 규칙만으로는 부족하다 — 제목이 아예
  없으면 순서를 정할 대상이 없다. 404·로그인·권한 없음·오류 화면도 대상이다.
- **정적 페이지 제목은 그 화면의 `<h1>`·헤더 메뉴와 같은 어휘를 쓴다.** 탭과 화면이 다른 이름으로
  같은 곳을 부르면 사용자가 두 개를 따로 외워야 한다.
- **앱 이름은 뺄 수 없다.** 전 앱 파비콘이 **같아서** 파비콘은 마리아임만 알려주고 앱끼리는 구분하지
  못한다. 방문기록·북마크·OS 창 전환에서 맥락이 사라진다.

### 동적 제목 (업무 데이터)

- **허용한다**(사용자 결정 2026-08-21) — 카드·레코드 제목을 탭에 싣는다. 그게 여러 창을 구분하는
  가장 실질적인 정보다.
- **단 환자·인사 식별정보는 제외한다.** 탭 제목은 화면 밖으로 샌다 — 방문기록, 브라우저 동기화로
  다른 기기, OS 창 목록, 화면 공유, 스크린샷. sns 카드 제목은 콘텐츠 기획 주제라 이 단서에
  걸리지 않는다. claim·labs 처럼 환자 정보를 다루는 앱에서 레코드 상세 화면이 생기면 이 단서를
  먼저 적용한다(2026-08-21 실측: 두 앱 모두 레코드 상세 라우트가 아직 없다).
- **정규화는 필수다.** 원문을 그대로 `<title>` 에 넣지 않는다.
  - NFC 정규화 → 개행·연속 공백 접기 → 제어문자·양방향 override(U+202A~U+202E, U+2066~U+2069) 제거
  - **순서 주의**: 공백 접기가 **먼저**다. 개행·탭도 제어문자 범위(U+0000~U+001F)라 제거를 먼저 하면
    줄바꿈이 지워져 앞뒤 단어가 들러붙는다(`9월\n두줄레터` → `9월두줄레터`). sns 구현에서 실제로
    난 버그이고 스모크가 잡았다.
  - **40 grapheme 상한 + `…`.** `slice(0, 40)` 은 이모지·조합 문자를 반으로 자르므로
    `Intl.Segmenter` 로 자소 단위를 센다. **40 은 브라우저 한계가 아니라 조직 정책값**이다.

### 구현 함정 (Next.js App Router)

- ⚠ **`layout` 의 `title.template` 은 같은 세그먼트의 `page` 에 적용되지 않는다**
  (Next 공식 문서). 루트 `app/page.tsx` 에 `title: "상황판"` 을 쓰면 탭에 `상황판` 만 뜨고
  앱 이름이 사라진다. **루트 페이지는 전체 문자열을 직접 조립**한다(`withAppTitle()`).
  템플릿만 믿으면 첫 화면부터 표준을 벗어난다.
- ⚠ **`generateMetadata` 는 페이지와 같은 인가를 써야 한다.** ID 만으로 레코드를 읽으면
  **제목만 새는 구멍**이 된다 — 권한 없는 사용자의 HTML·탭·방문기록에 레코드 제목이 남는다.
  페이지 본문의 게이트가 먼저 돈다고 가정하면 안 된다. 인가를 포함한 loader 를 `cache()` 로
  감싸 페이지와 공유한다(Next 가 자동 중복 제거하는 것은 `fetch` 뿐 — Prisma 조회는 두 번 돈다).
- `global-error.tsx` 는 루트 레이아웃을 **대체**해 `metadata` 가 먹지 않는다 → React `<title>` 로
  직접 달고, 앱 이름은 같은 상수를 참조한다(sns 는 여기만 앱 이름이 달랐다).
- `<title>` 과 `openGraph.title` 은 분리한다. 대외 홍보용 OG 제목에 사내 템플릿을 기계적으로
  붙이지 않는다.

### 검사의 한계 (정직 표기)

`tab-title(static)` 이 보는 것: 루트 layout 의 `default`·`template` 존재와 형식 · 모든 routable
page 의 제목 선언 존재 · 잘못된 구분자 · 루트 page 의 템플릿 오의존.
**보지 못하는 것**: 제목이 사람에게 적절한가 · 두 제목이 의미상 고유한가 · 업무 데이터의 실제
기밀 등급 · 크롬에서 몇 글자가 보이는가 · 조회 권한이 도메인 정책과 같은가. 이 구간은 §8
사전 확인 게이트와 사람의 눈이 맡는다.

## 1-4. 액션 색·위계 (v1.14, 2026-08-23 신설 · v1.18·v1.19·v1.20, 2026-08-24 개정)

일반 화면의 버튼·링크 색을 정하는 규칙이 **이 문서에 없었다** — 버튼 색이 나오는 유일한 지점이
§3 로그인 템플릿(`bg-maria-green`)이었고, 그 공백 속에서 같은 "저장" 버튼이 앱마다
틸/딥그린으로 갈렸다(규칙 위반이 아니라 **규칙 부재**, 2026-08-21 실측). 이 절이 그 공백을 채운다.

근거 = 디자인 아이덴티티 전수조사(maria-ui `docs/census/`)의 업무 행동 분류 **466행 실측**과
사용자 결정 3건(2026-08-22, `s3/S3-ACTION-TAXONOMY.md` §5):
- **D-1** 분류 3축 — 주행동 8종(축A) · 복구성 6단(축B) · 부수효과 플래그(축C)
- **D-2** 시각 위계의 결정자 = **max(영향, 복구곤란도, 외부파급, 민감정보, 일괄범위)**
- **D-3** 색은 **두 겹** — `의미 톤`(중립·확정·경고·파괴) × `강조`(1차 채움·2차 테두리·3차 평문),
  그리고 **대비 하한 = 텍스트 4.5:1 · 비텍스트 3.0:1**
- **D-4** 화면마다 판정이 갈리던 **공통 쟁점 5건의 정책 확정**(2026-08-24 사용자 결정 Q1~Q5, 상신본 =
  maria-ui `docs/census/s6/S6-TONE-EMPHASIS-DECISION.html`) — notify 3종 분류 · money·B5 무예외 ·
  파괴는 데이터 소거에만 · 권한 경계 변경(authz) 승격 · 1차 채움은 정적 단일 액션만.
  이 5건이 v1.18 개정의 내용이며, 아래 본문에 각각 성문화돼 있다.

### 대비 하한 — 모든 색 규칙에 선행한다

- **텍스트 4.5:1 · 비텍스트(식별에 필요한 테두리·아이콘·상태 표식) 3.0:1.**
  WCAG AA 를 **바탕으로 한 내부 하한**이며, AA 의 큰 글자(3:1)·incidental·로고 예외는 **쓰지 않는다**.
  ("WCAG AA = 예외 없음"이라 적으면 규격 오인용이다 — 예외를 안 쓰는 것은 우리 결정이다.)
- **비활성(disabled) 상태는 하한의 대상이 아니다 — 단, 이것은 "무예외"의 유일한 의식적 예외다.**
  ⚠ 정확히 쓰면: 비텍스트(1.4.11)는 WCAG 문언 자체가 inactive 를 제외하지만, **텍스트(1.4.3)의
  비활성 컴포넌트 제외는 incidental 예외에 속한다** — D-3 이 "incidental 예외를 쓰지 않는다"고
  했으므로 disabled 텍스트 제외는 예외 0건이 아니라 **예외 1건을 의식적으로 남기는 결정**이다
  (비활성 버튼에 4.5:1 을 요구하면 활성과 구별이 안 되는 실무 근거. 2026-08-23 Codex 검토로 문언
  모순 발견 → **같은 날 사용자 승인 완료** — disabled 는 하한 대상에서 제외하며, 이것이 무예외
  원칙의 유일한 승인 예외다. 검사 구현도 disabled 를 제외한다).
  비활성임을 색으로만 알리지 않는다(`disabled` 속성 병행).
- **순수 장식은 비텍스트 하한의 대상이 아니다.** 판정 기준은 "그 경계선이 식별에 필수인가"다 —
  입력 외곽선 = 필수(하한 적용), 카드 장식 테두리·구분선 = 장식(대상 아님).

### 의미 톤 — 행동의 성질이 정한다

기본 톤은 축A 주행동으로 정하고, 축B·축C 는 **승격만** 시킨다. 강등은 없다 —
무게를 낮출 때는 톤이 아니라 **강조**를 낮춘다.

| 톤 | 기본 대상(축A) | 승격 조건 |
|---|---|---|
| **중립** | `nav` 열람·이동 · `dismiss` 닫기·이탈 | — |
| **확정** | `edit` 저장 · `commit` 확정 · `publish` 발신 · `export` 반출 · `revert` 상태 회귀(데이터를 지우지 않는 것) — 저위험 일반 | — |
| **경고** | (기본 대상 없음 — 승격으로만 진입) | 확정 대상 중 **① 화면 밖으로 나가 회수 불가**(`notify③` 제3자 업무 유발 · `pii` 개인정보 반출 · `authz` 권한 결정) 또는 **② 되돌릴 수 없이 잃음**(`wipe` · B4·B5 중 **소실형**) 인 것. **`money`·`bulk` 는 톤 인자가 아니다**(아래 '대가는 톤이 아니다') |
| **파괴** | `discard`·`revert` 중 **의도된 주효과가 데이터(저장 전 입력 포함)의 삭제·폐기·초기화인 실행 액션** · `wipe` 플래그(저장 안 된 입력 폐기) | (이미 최상) |

- **비가역에는 세 종류가 있고, 색이 다뤄야 하는 것은 뒤의 둘뿐이다** (v1.20, 2026-08-24 사용자 재결정).

  | 종류 | 예 | 색 |
  |---|---|---|
  | **얻는 비가역** — 대가를 치르고 결과물을 얻는다 | 이미지·영상·음성 생성(유료 호출), AI 초안 뽑기 | **확정** — 업무를 앞으로 나아가게 하는 행위다 |
  | **잃는 비가역** — 입력·데이터가 사라진다 | 손입력 덮어쓰기, 옛 입력 폐기, 미저장 초안 버리기 | **경고**(지우는 것이 주효과면 **파괴**) |
  | **밖으로 나감** — 회수할 수 없고 남의 일이 된다 | 알림톡·슬랙 발신, 개인정보 반출, 권한 결정 | **경고** |

  v1.18 까지는 셋을 `money`·B5 하나로 묶어 **같은 색**을 줬다. 그 결과 도구의 주행동(생성)이
  경고 톤이 되어 "앞으로 나아가는 행위"라는 사용자 인지와 어긋났다(S7 실물 확인, 2026-08-24).
  색은 **결과가 어디로 가고 무엇이 사라지는가**를 말하고, **얼마를 치르는가**는 색이 아니라
  비용 표시와 확인 게이트가 말한다.
- **대가는 톤이 아니다 — `money`·`bulk` 는 승격 인자에서 뺀다. 대신 두 의무를 만든다.**
  - **비용 표시 의무(`money`)**: 유료 호출 버튼은 **누르기 전에** 무엇이 얼마나 드는지 화면에서
    읽을 수 있어야 한다(단가·예상 건수·예상 비용 중 그 화면에서 말이 되는 것). 접어두지 않는다.
  - **확인 게이트 의무(`bulk` + 비가역)**: 한 번 눌러 **여러 건이 한꺼번에** 과금·발신·소실되는
    행동은 실행 전에 범위를 보여주고 확인을 받는다. 게이트가 없으면 그것이 부채다 — 색으로
    대신하지 않는다(전수조사 F-6·F-7 이 이미 그 부채를 세어 두었다).
- 이 표가 D-2 의 `max()` 를 옮긴 것이다 — 인자 중 하나라도 무거우면 **톤이** 올라간다.
  **`max()` 가 정하는 것은 톤뿐이고 강조는 아래 '강조' 절의 배치 규칙이 따로 정한다** — D-2 문언의
  "시각 위계"를 두 겹 전체로 읽으면 오독이다(v1.18 정정).
- **플래그는 D-2 다섯 인자의 *입력*이지 여섯 번째 인자가 아니다.** 대응: `authz` → 영향 ·
  B4·B5 **중 소실형** → 복구곤란도 · `notify③` → 외부파급 · `pii` → 민감정보.
  `money`·`bulk` 는 v1.20 에서 **톤 인자에서 빠졌다**(각각 비용 표시 의무·확인 게이트 의무로 이동).
  이 대응대로 **원장 플래그(축C·축B)로 기계 대조하는 것이 목표**이며, v1.18 은 축C `authz`
  **신설과** `notify` ①②③ **세분을 이행 조건으로 지정**했을 뿐이다 — **현 원장에는 `authz` 가 없고
  `notify` 도 단일 플래그다**(maria-ui `docs/census/s3/taxonomy-map.tsv`·`apply-taxonomy.mjs` 실측
  2026-08-24). 스키마·검사 반영 전까지 이 절의 승격 판정은 **자동 판정되지 않는 수동 검토 대상**이다
  (아래 '수동 판정 게이트'·'이행 상태').
  어느 플래그·복구성에도 걸리지 않는 잔여 '영향'은 정의상 계속 사람 판정이다.
- **notify 승격은 수신자 기준 3종으로 판정한다** (Q1, 2026-08-24 사용자 결정). 종전 문언
  ("좁게 읽는다")은 방향만 주고 경계를 주지 않아 화면마다 재량이 남았다 — 아래로 명문화한다.

  | # | 알림의 성격 | notify 승격 | 예 |
  |---|---|---|---|
  | ① | 요청자 **본인**에게 가는 인증·단순 접수 확인 | **없음** | 로그인 OTP 재발송 · 제출 접수 확인 메일 |
  | ② | **당사자**에게 가는 결정 **결과 통지** | **없음** | SSO 승인·거부 결과 통보 |
  | ③ | **제3자**에게 작업·판단·후속 행동이 **생기는** 알림 | **승격** | 접근 신청(관리자 처리 대기 발생) · 외주 작가 수정 요청 · 제작 의뢰·물품 신청 접수 |

  - ①을 제외하지 않으면 로그인 화면의 OTP 버튼까지 경고 톤이 된다(2026-08-23 Codex 검토).
  - **②는 notify 로 승격되지 않을 뿐, 다른 축으로는 승격될 수 있다** — 축은 독립이고 판정은 언제나
    `max()` 다(예: SSO 승인 = ②이지만 `authz` 로 경고 승격). ②를 "승격 없음"으로 읽고 톤을
    확정으로 고정하는 것은 오독이다.
  - **용어**: `당사자` = 그 결정의 신청자 또는 직접 대상자. ②는 **이미 끝난 결정의 결과만** 전하고
    새 작업·판단·응답을 요구하지 않는 통지다. 결과 통지가 수신자에게 **후속 행동을 요구하면 ③**이다.
  - 한 행동이 여러 수신자에게 알림을 보내면 **수신자별로 판정하고, 하나라도 ③이면 그 행동은 ③**이다
    (`max()` 원칙 그대로).
  - 원장에는 축C `notify` 를 ①②③ 으로 세분해 기록한다(승격 판정은 ③만). **세분 기록 전까지는
    기계 검사가 불가능하며 아래 '수동 판정 게이트' 소관이다.**
- **권한 경계 변경(`authz`)은 승격 사유다** (Q4, 2026-08-24 사용자 결정). 역할·소속·접근 범위를
  주거나 빼앗는 행동은 **그 이후 모든 행동의 전제**를 바꾼다 — 스스로 데이터를 지우지 않아도 경고
  톤이다(예: console SSO 승인·권한 회수 — 거부는 아래 '범위' 항 참조). 종전에는 §1-4 에서 유일하게 사람 판정으로 남겼던 '영향'
  인자로 사례마다 다투던 자리다.
  - **범위(v1.20 확장)**: 다른 사람의 **권한·접근 상태를 결정하는 행동** 전부 — 부여·변경·회수에
    더해 **거부·반려·사용 차단**을 포함한다. v1.18 은 "실효 권한을 바꾸지 않는 거부"를 뺐는데,
    `money` 를 톤에서 뺀 v1.20 에서는 거부가 어느 인자에도 안 걸려 확정 톤으로 떨어진다 —
    남의 접근을 막는 결정이 평범한 저장과 같은 색이 되는 것은 이 절의 취지에 반한다.
    판정 기준은 "**내 것에 대한 결정인가, 남의 접근에 대한 결정인가**"다.
    신청자 본인의 **신청 제출**은 자기 것이라 해당하지 않는다(그쪽은 `notify③` 로 걸린다).
  - 원장 축C `authz` **신설이 이행 조건**이다(현 원장에 없음 — 위 플래그 항).
- **파괴 톤은 데이터를 지우는 행동에만 쓴다** (Q3, 2026-08-24 사용자 결정).
  - **데이터 소거를 동반하지 않는 상태 전이**(권한 거부·회수, 반려, 보류)는 파괴가 아니다 —
    축A 기본 톤에 승격 규칙을 적용해 그 행동에 실제로 기록된 `authz` 또는 B4 로 **경고까지** 오른다.
    "상태 전이면 무조건 경고"가 아니라 플래그·복구성으로 판정한다.
  - **상태 전이가 데이터 소거를 동반하면 파괴가 우선**한다 — 두 성질은 배타가 아니다(Codex 지적).
  - **확인 게이트를 여는 트리거(축C `opener`)는 최종 실행 액션의 톤을 상속한다.** 사용자가 보는
    것은 트리거 색이고, 트리거만 순하면 §1-4 가 막으려던 "평시 회색 삭제 버튼"(전수조사 F-3 실사고)이
    되돌아온다. **강조는 상속하지 않는다** — 게이트 안의 확정 버튼 2차, 인라인 반복 트리거 3차
    (S6 결정 T 묶음 16행의 전제와 같다). 반대로 `opener` 라는 이유로 파괴 톤을 면제하지 않는다.
  - ⚠ **상속하는 것은 "확인 게이트"뿐이다** (v1.19 정밀화 — S7 구현 중 경계가 갈렸다).
    판정 기준: 트리거를 누른 뒤 **사용자가 새로 결정할 내용이 없고 확인·사유만 남는가**.
    - 상속 O = 삭제 확인창 · 사유 입력 후 실행(드랍·거부·회수·CSV 반출) — 트리거가 곧 그 행동으로 읽힌다.
    - 상속 X = **폼·패널을 여는 것**(예: "수신자 추가" → 입력 폼, "초안으로 시작하기" → AI 패널).
      아직 무엇을 할지 정하지 않았고 실행은 폼 안의 저장 버튼이다. 여기까지 상속시키면 화면의
      거의 모든 버튼이 승격 톤이 되어 변별력이 사라진다(labs·popo 실측으로 확인).
  - 빨강을 삭제·폐기에만 남겨야 빨강이 신호로 작동한다(2026-08-12 "빨강은 삭제·폐기 관례색"
    결정의 연장 — sns 수정 요청 버튼 주석에 성문).
- ↩️ **Q2(money·B5 무예외)는 v1.20 에서 번복됐다** — 규칙을 예외로 뚫은 것이 아니라 **인자를 바꿨다.**
  Q2 는 "도구의 주행동이라는 이유로 면제하지 않는다"였고 그 자체는 지금도 옳다(면제 조항은 없다).
  바뀐 것은 `money` 가 애초에 톤 인자가 아니게 된 것이다(위 3분류) — 그래서 popo 생성 4버튼은
  **예외가 아니라 규칙대로** 확정 톤이다. 반복 작업의 피로는 여전히 톤이 아니라 **강조**로 조절한다.
  ⚠ 색이 확인 게이트를 대체하지 않는다는 단서는 그대로이고, v1.20 은 그 부담을 색에서
  **게이트·비용 표시로 옮겼다** — 옮긴 만큼 그쪽을 실제로 만들어야 한다(위 두 의무).
- ⚠ **라벨이 아니라 실제 효과로 판정한다.** 전수조사에서 자동 라벨 판정 47건이 코드 직독으로
  뒤집혔다(라벨 "취소"가 실제로는 업무 종결, "수정 요청"이 실제로는 외부 슬랙 발신).

### 강조 — 화면 안 배치가 정한다

| 강조 | 형태 | 규칙 |
|---|---|---|
| **1차** | 톤 색 채움 + 흰 글자 | **활성 뷰 하나에 원칙 1개** · 그 뷰에 **한 번만 나타나는** 액션에만 허용(반복 인스턴스 불가) |
| **2차** | 톤 색 1px 테두리 + 톤 색 글자 (배경 투명·흰색) | — |
| **3차** | 톤 색 글자만 | 빈번·저결과 행동 |

- **반복·다중 채움의 계산 단위** (Q5, 2026-08-24 사용자 결정). "화면당 1차 1개"가 목록 화면에서
  무너지는 것을 막는 계산 규칙이다.
  - **계산 단위 = 활성 뷰.** 같은 안정 상태에서 **동시에 보이고 조작 가능한** 범위가 한 뷰다.
    상호배타 조건 분기(탭·단계·상태별 렌더)에서 한 번에 하나만 보이는 후보는 **각 상태에서**
    1차가 될 수 있다. 모달이 열려 배경 조작이 막히면 **모달을 별도 활성 뷰로 센다**(§1-5).
  - **한 페이지가 순차 단계 섹션으로 이어져 있으면 섹션마다 하나의 활성 뷰로 센다**
    (v1.20 정밀화). 예: popo 장면 스튜디오 = 이미지 만들기 → 영상 만들기 · sns 상세 = 판정 →
    완료 → 발행. 근거는 두 가지다 — ① 사용자는 스크롤하며 한 번에 한 섹션을 다룬다
    ② 페이지 전체를 한 뷰로 세면 긴 업무 화면은 **어느 단계에도 주행동을 줄 수 없게** 된다.
    대신 **한 섹션 안에서는 1차 1개를 엄격히** 지킨다 — 폼을 여는 버튼이 폼이 열린 뒤에도
    채움으로 남아 저장 버튼과 나란히 서는 것이 대표적 위반이다.
  - **1차 채움은 활성 뷰에 한 번만 나타나는 액션에만 허용한다.** 목록·그리드의 행마다 복제되어
    동시에 보이는 액션은 같은 행동이라도 **최대 2차 테두리**다(예: SSO 목록의 행별 승인 = 경고 2차).
  - 한 뷰에 채움 후보가 둘 이상이면 **`화면 대표 액션` 하나만 1차**로 남기고 나머지는 2차로 내린다
    (예: sns 상세 = 제작완료·내용확정 1차, 같은 화면의 피드백 등록 2차).
  - ⚠ **`화면 대표 액션` 은 축A 의 `주행동 8종` 과 다른 개념이다**(동음이의 — Codex 지적).
    축A 는 행동의 종류(nav·edit·commit…)이고, 대표 액션은 **그 화면이 존재하는 이유가 되는 액션
    하나**다. **기계가 고르지 않는다** — 행별 판정 원장(또는 화면 명세)에 대표 액션을 명시하고,
    명시가 없으면 구현자가 추정하지 말고 **후보 전부를 2차로 두고 수동 판정을 요청**한다.
  - 반복 인스턴스를 "한 액션"으로 세는 대안은 기각했다 — 화면에는 여전히 채움이 여러 개 보여
    원칙이 체감되지 않는다.
- **같은 행동이라도 결과가 가벼우면 톤은 유지하고 강조만 낮춘다.** D-3 의 결정 지점 그대로 —
  로컬 슬롯 제거(discard·B0, 빈번·무해)와 재입력이 필요한 삭제(discard·B4)는 **둘 다 파괴 톤**이되
  전자는 3차 평문, 후자는 1·2차. 한 겹 체계의 경고 피로를 이렇게 피한다.
- **2차·3차의 투명 배경은 실제 바탕색에서 하한을 다시 만족해야 한다.** Q5 로 2차가 늘어나는데
  2차·3차는 배경을 칠하지 않으므로, 카드·표 행·강조 배경 위에 놓이면 대비가 흰 배경 기준과 달라진다 —
  글자 4.5:1 · 테두리 3.0:1 을 **그 바탕색으로 계산**해 미달하면 흰 배경(또는 검증된 톤×배경 조합)을
  쓴다. 대비 하한이 언제나 선행한다(위 '대비 하한' 절).
- **평상시 상태에서 식별 가능해야 한다 — hover 에만 나타나는 색·표시는 식별 수단으로 인정하지 않는다.**
  터치 기기에 hover 는 없다(전수조사 F-3: 되돌리기 없는 삭제 버튼이 평시 회색이던 실사고 —
  hub `tool-shell` 3건은 D-5 로 처분 완료).

### 수동 판정 게이트 — 정본을 *정상 적용*하기 위한 사람 판정 (v1.18 신설)

§8 은 **정본에서 벗어나는 예외**의 사전 승인·기록 절차다. 이 절은 그것과 다르다 — 정본을
**그대로 적용하는 데** 필요한 사람 판정이고, 기계가 대신할 수 없다. 둘을 같은 절에 두면
"승인된 이탈"과 "정상 판정"이 다시 섞이므로 분리한다(Codex 지적 2026-08-24).

| 판정 항목 | 기계가 못 하는 이유 |
|---|---|
| 잔여 '영향' | 플래그 어디에도 안 걸리는 파급 — 정의상 사람 판정 |
| `notify` ①②③ | 수신자의 역할과 후속 업무 발생 여부가 코드에 적혀 있지 않다 |
| `authz` 여부 | 실효 권한이 바뀌는지는 시스템 의미론 |
| `discard` 의 주효과가 데이터 소거인지 | 라벨이 아니라 실제 효과로 판정해야 한다 |
| 활성 뷰 경계 | 조건부 렌더·모달·반응형은 런타임 합성 결과 |
| 화면 대표 액션 | 제품 의도 |

- 판정은 **행별 원장에 판정자·근거·예상 톤·예상 강조를 적어** 남긴다. 적히지 않은 행은
  **채택 완료로 세지 않는다.**
- 검사(ui-audit)가 할 수 있는 최대치는 **"원장에 선언된 판정과 구현된 클래스가 일치하는가"**다 —
  **선언된 판정이 사실인지는 검사하지 못한다.** 이 한계를 검사 모듈 머리 주석에도 같은 문장으로
  적는다(정직 표기 관행).
- **톤×강조의 앱 채택 상태는 토큰 채택(`s14adopted`)과 분리한다.** 현 `s14adopted` 는 토큰 9종이
  목표값이면 **자동 채택**으로 간주하는데(maria-ui `ui-audit-s14.mjs:115` `!!appCfg.s14adopted ||
  allWant` 실측), 그 조건은 이미 7앱이 만족한다 — 재사용하면 톤×강조 미이행 앱이 조용히 "채택"으로
  읽히는 **거짓 완료**가 된다. 별도 상태(예: `s14ActionsAdopted`)를 두고 행별 원장 갱신·코드 반영·
  검사 통과 전에는 올리지 않는다.

## 1-5. 다이얼로그 — 시스템 알럿 대체 (v1.17, 2026-08-24 신설)

제품 화면에서 **`window.alert` / `window.confirm` / `window.prompt` 를 쓰지 않는다**
(사용자 결정 2026-08-23, 마리아·sidoyu 공통). 브라우저 기본 팝업은 스타일을 못 입히고,
렌더를 통째로 막고, 창 상단에 떠서 어느 화면의 물음인지 알 수 없다.

### 규칙

- 대체 구현 정본 = **`@maria/modal`** — `AlertDialog`(알림) · `ConfirmDialog`(확인/취소,
  `tone=default|warning`) · `ReasonDialog`(감사 기록용 사유 입력, 최소 길이 게이트) +
  공용 껍데기 `ModalShell`. 네이티브 `<dialog>` + `showModal()` 기반이라 포커스 가두기·
  배경 inert·Escape 처리를 브라우저 top layer 에 위임한다.
- **div 오버레이 다이얼로그 자작 금지.** focus trap·포커스 복귀가 수작업이 되고, 실제로
  그 부채가 남았던 선행 구현(mou 舊 modal.tsx)이 이 정본의 반면교사다. 앱 고유
  다이얼로그가 필요하면 `ModalShell` 위에 조합한다.
- 계약 5항목(설치본이 지켜야 하는 동작 — 정본 파일 머리 주석과 동일):
  1. **열림 = 마운트**(open prop 없음, 부모 조건부 렌더). 닫힘 = onClose/onCancel →
     부모 state 제거 → unmount **단일 경로**(Escape 도 preventDefault 후 같은 경로).
     같은 자리에서 용건만 바꿔 연속 재사용하면 `key` 로 강제 remount(unmount 가 실제로
     일어나야 입력 상태가 소거된다).
  2. **초기 포커스 = 명시 지정**(showModal 직후 ref.focus) — Alert=확인 버튼,
     Confirm=취소 버튼(안전 기본값), Reason=사유 입력란. DOM 순서에 맡기지 않는다 —
     message 가 ReactNode 라 소비처가 링크를 넣으면 "첫 focusable"이 조용히 바뀐다
     (Codex 2026-08-24 지적으로 초판의 DOM 순서 위임을 명시 지정으로 개정).
  3. 닫힌 뒤 **열기 전 요소로 포커스 복귀 시도**(preventScroll — 여는 사이 opener 가
     disabled 되면 복귀할 곳이 없어 시도만: 수용된 한계).
  4. **pending=true 동안 컴포넌트가 제공하는 닫힘 경로**(Escape·바깥 클릭·취소)를
     차단한다. **절대 잠금 보장이 아니다** — 새로고침·뒤로가기는 범위 밖이고, 브라우저가
     cancel 없이 강제로 닫으면(연속 Escape 등) onClose 로 부모 state 를 동기화한다.
  5. **동시 modal 1개 — 중첩 금지.** 필요하면 부모가 순차로 연다.
- 색은 §1-4 를 따른다: 확정 톤 버튼 `popo-teal-700`(+hover `900`) + **흰 글자**
  (`btn-emphasis-fg`=#FFF — 아이보리 아님) · 경고 톤 `state-warning-fg`(+hover 는 전용
  토큰 `state-warning-fg-hover`) · 취소 버튼·사유 입력 외곽선 `border-input`(식별 테두리).
- 한글 사유 입력의 Enter 는 **IME 조합 확정 Enter 를 제출로 오인하지 않는다**
  (isComposing 가드 — 정본에 포함, 지우면 modal-canonical 이 잡는다).
- 다이얼로그는 "떠 있는 층"이라 그림자 허용(§3 의 카드 shadow 금지와 다른 층위 —
  그 조항 원문이 이미 "그림자는 드롭다운·모달 등 떠 있는 층에만"이라고 예외를 명시한다).

### 검사 (ui-audit)

- `no-system-alert(static)`: 주석 제거 후 `window|globalThis|self` 접두 호출(옵셔널
  체이닝·bracket 접근 포함) + bare 호출을 UI 소스(.tsx/.ts/.jsx/.js)에서 검출(FAIL).
  `scripts/`·테스트 파일 제외, 읽기 실패는 판정 불완전(WARN)으로 노출. claim 은 면제 —
  앱 폐기(2026-08-22) **뒤에** 신설된 규칙이라 동결 이력에 소급하지 않는다.
- `modal-canonical(static)`: 설치본 `components/ui/modal.tsx` 를 **정본 전문과 정규화
  대조**(주석 제거·공백 1칸) — 정본은 검사 시점에 maria-ui 정본 파일에서 직접 파생하므로
  기대값이 따로 늙지 않는다. 안전 기제 조각 5종(포커스 복귀 cleanup·Escape 단일 경로·
  backdrop press-시작점 가드·IME Enter 가드·취소-앞 버튼 순서)은 실패 진단 라벨.
  파일이 없으면 판정 제외(도입 시 자동 편입), 읽기 실패는 FAIL.

### 검사의 한계 (정직 표기)

- 문자열/eval 속 호출, 간접 참조(`const f = window.alert; f()`), alias 재수출은 정적으로
  못 본다. 로컬 함수 이름이 `confirm`/`alert`/`prompt` 면 오탐한다(이름을 바꾸는 게 답).
- div 오버레이 자작 금지는 기계 강제가 없다(§8 사전 확인 게이트가 맡는다) — "무엇이
  다이얼로그인가"는 의미 판단이라 자동 차단이 오탐을 만든다.
- pending 잠금·포커스 이동은 정적 검사가 **코드 원문의 존재**만 본다 — 런타임 동작
  실측은 설치 시점 브라우저 검증(§5 수동 확인)이 맡는다.

## 3. 로그인 페이지 템플릿

전 앱 동일 템플릿(2026-06 claim·console·popo·mou 4앱에서 추출 — claim 은 2026-08-22 폐기, 현재는 hub·labs·sns 포함 전 함대가 같은 규격). 공개 화면이라 미리보기로도 검증 가능.

- 바깥: `<main className="flex min-h-screen flex-col items-center justify-center bg-bg-ivory p-6">`
- 제목 블록: `<div className="mb-6 text-center">` 안에 `<h1 className="text-2xl font-bold tracking-tight text-text-primary">{앱이름}</h1>` + `<p className="mt-1 text-sm text-text-body">{한 줄 설명}</p>`
- 폼 카드: `<… className="w-full max-w-sm space-y-4 rounded-lg border border-border-default bg-bg-default p-6">` (2026-07-08: 장식용 `shadow-sm` 제거 — 경계는 1px border로. 그림자는 드롭다운·모달 등 떠 있는 층에만.)
  - 입력: `w-full rounded-md bg-bg-default border border-border-input px-3 py-2.5 text-sm focus:border-popo-teal-500 focus:ring-1 focus:ring-popo-teal-500`
    (v1.16: 테두리를 §1-4 에 따라 `border-border-input`(#6E827D)으로 **이행 완료** — `--border-default` 1.33 은
    식별 테두리 하한 3.0 미달이라 카드(장식)에만 남는다. focus 테두리·링은 비텍스트 3.0 충족이라 teal-500 유지.
    정본 부품(AuthPrimitives)·ui-audit `login(static)`·7앱 재동기를 한 묶음으로 갱신했다.)
  - 버튼: `w-full rounded-md bg-maria-green text-text-on-dark font-semibold py-2.5 hover:bg-maria-green-700 disabled:opacity-50`
  - 에러: `<div role="alert" className="rounded-md bg-state-error-bg px-3 py-2 text-sm text-state-error-fg">` (#FCEEED / #8B4540). **`role="alert"` 는 필수다** — 이 속성이 없으면 화면에는 사유가 떴는데 스크린리더에는 아무 일도 안 일어난 것과 같다(눈으로 볼 수 없는 직원은 "다음"을 눌러도 왜 안 넘어가는지 알 수 없다). `role="alert"` 가 `aria-live="assertive"`·`aria-atomic` 을 함의하므로 그 둘은 따로 적지 않는다. (v1.8)
  - **에러 영역은 항상 그려 둔다 — 조건부로 감싸지 않는다.** (v1.9) 호출부는 `{error && <AuthError …/>}` 가 아니라 `<AuthError message={error} seq={errorSeq} />` 다. 오류가 없을 때는 `sr-only` 로 남아 화면·레이아웃에 영향을 주지 않는다. 이유 둘:
    ① **live region 은 글이 들어오기 전부터 DOM 에 있어야 안내가 확실하다.** 영역과 글이 같은 순간에 삽입되면 읽지 않는 스크린리더가 있다.
    ② `seq`(오류 발생 횟수)를 넘겨 **DOM 변화를 보장한다** — 동기 검증 오류는 React batching 으로 `null → 같은 문자열` 이 커밋조차 되지 않기 때문이다. ⚠ **단 이것으로 "연속 동일 오류 재발표"는 해결되지 않는다(v1.10 에서 실측으로 정정).**
  - **브라우저 기본 유효성 검사를 끈다 — 폼에 `noValidate`.** (v1.10) `required` 는 **그대로 둔다**(스크린리더가 "필수 사항"으로 읽어주는 유용한 표시). 끄기 전에는 빈칸 제출 시 브라우저가 폼 제출 자체를 막아 앱의 빈칸 오류 문구가 **한 번도 표시된 적 없는 죽은 코드**였고, 대신 뜨는 브라우저 말풍선은 실측에서 **낭독되지 않았다**(필드 설명만 읽힘). 메시지는 우리 `role="alert"` 영역이 맡는다.
  - **입력 필드는 오류와 연결한다.** (v1.9) 오류가 있을 때 해당 입력에 `aria-invalid="true"` + `aria-describedby={AUTH_ERROR_ID}`. 연결이 없으면 필드로 이동했을 때 "무엇이 잘못됐는지"가 다시 안 읽힌다(오류 발표를 놓쳤거나 나중에 되짚는 경우).
  - **이메일 입력 필드에 "username" 신호를 쓰지 않는다 — `id`·`name`·`autoComplete` 전부 `email` 로.** (v1.11)
    비밀번호 관리자 확장(iCloud 암호 실측, 1Password 계열 동류)이 "username" 신호가 하나라도 있으면
    로그인 필드로 붙어 제안 오버레이를 띄우고 **Enter(암묵적 제출)를 가로챈다** — 버튼 클릭·Tab 이동은
    되는데 Enter 만 안 되는 증상. 이 SSO 는 비밀번호가 없어(OTP 단독) username 자동완성을 잃을 것도 없다.
    2026-08-18 사용자 실브라우저 A/B 실측: id·autoComplete 중 **하나만 "username" 이어도 차단**,
    둘 다 "email" 이면 통과(sns 가 그 산 증거였다).
  - 인증 코드 필드 라벨 옆 **OTP 도움말**: `@maria/auth-primitives`의 `AuthOtpHelp` — `?` 아이콘(`h-4 w-4 cursor-help rounded-full border-border-default`), hover·키보드 포커스·모바일 탭 시 실제 인증 메일을 축소 재현한 팝오버. 팝오버는 떠 있는 층이라 그림자 허용. 메일 재현부는 외부 메일 모사라 마리아 토큰이 아닌 원문 색·서체(Helvetica·`#111827`)를 쓴다(실물과 같아야 사용자가 알아봄). 예시 코드는 가짜 고정값 852937. (v1.6)
- 푸터: `<p className="mt-6 text-center text-xs text-text-muted">마리아의료재단 CX부</p>`

### 3-1. 로그인 문구 표준 (v1.6, 2026-08-04 사용자 결정)

사용자 노출 문구에서 **"가입"이라는 말을 쓰지 않는다** — 사내 SSO에 회원가입 개념이 없기 때문(계정은 이메일 인증만으로 생기고, 앱 권한은 신청·승인이다). 세 단어로 통일:

| 개념 | 표준 용어 | 예 |
|---|---|---|
| 계정이 SSO에 있음/없음 | **등록** | "등록된 이메일은 즉시 로그인됩니다" · "등록되지 않은 이메일입니다" |
| OTP 본인 확인 | **이메일 인증** | hub 신규 버튼 "인증하기" |
| 앱 권한 요청(전 앱 공통) | **접근 신청** | popo·claim 신규 버튼 "접근 신청" · console "접근 승인" |

운영자 화면·Slack 알림도 같은 용어를 쓴다(직원-운영자 용어 이원화 금지). 코드 식별자·계약 문서 내부 용어는 불변.

## 6. 금지·주의

- ❌ `globals.css`에서 `@import` **뒤**에 `:root { --text-on-dark: … }` 등으로 토큰 **재정의(override)** — 토큰을 가려 라이브가 갈린다(2026-06-04 console·popo 실제 사고).
- ❌ 앱별로 hex 값을 손으로 옮겨 적기 — `tokens/design-tokens.css`를 파일째 가져올 것.
- ❌ 본문 페이지를 임의로 더 좁히기(7xl 통일 위반).
- ❌ **Lucide 외 아이콘 세트를 추가로 들이기**(§1-2). 획 굵기·광학 크기·모서리가 세트마다 달라 한 화면에 섞이면 바로 보인다. 필요한 글리프가 없으면 인라인 `<svg>` 를 그리기 전에 §8 사전 확인.
- ❌ **`popo-teal`(500) 채움 위에 글자를 얹거나 `popo-teal` 을 글자색으로 쓰기**(§1-4). 텍스트 대비 하한(4.5:1) 미달 — 글자가 걸리면 `popo-teal-700`.
- ❌ **행동의 톤·강조를 hover 에만 표시하기**(§1-4). 터치 기기에 hover 는 없다.
- ❌ **`window.alert`/`confirm`/`prompt` 및 div 오버레이 다이얼로그 자작**(§1-5). 대체 = `@maria/modal`, 앱 고유 다이얼로그는 `ModalShell` 위 조합.
- ⚠️ 검증은 토큰 파일이 아니라 **배포된 CSS**로(override가 파일엔 안 보이고 라이브에만 나타남).

> **자동 검사 범위(2026-07-31~)**: 위 재정의 사고는 오랫동안 `--text-on-dark` 한 색에만 방어가 있었다.
> 나머지 브랜드 색은 ui-audit 이 클래스 **이름**(`bg-maria-green`)만 보고 그 이름이 가리키는 **값**은
> 아무도 보지 않았다. 이제 `brand-color(live)`·`brand-color(static)` 이 `--maria-green` `--popo-teal`
> `--bg-ivory` 의 구체값을 정본과 대조한다(스케일 변형 `--maria-green-700` 등은 대상 아님).
> 라이브 쪽이 확정 판정 — static 은 배포 전에 잡는 층이다.

## 7. 비상 fallback (레지스트리 접근 불가 시)

`@maria` 레지스트리는 인증 게이트(private)다. 토큰 만료·장애·긴급 hotfix로 접근이 막히면:
1. 이 repo `tokens/design-tokens.css`를 직접 복사(레지스트리 없이도 토큰 확보).
2. 헤더/로그인은 `internal-service-header-v1.md`·본 문서 §3 코드를 카피.
3. 레지스트리 토큰 복구는 maria-ui `RUNBOOK.md`.

→ **레지스트리가 막혀도 이 repo만 있으면 수동으로 일관성 적용 가능.**

## 8. 예외

기준에서 벗어나야 하는 합당한 이유가 있으면 **먼저 명시 확인** 후 진행하고, 이 문서에 사유와 함께 기록한다.

기록되지 않은 예외는 예외가 아니라 **드리프트**다. 다음 사람이 "승인된 이탈"과 "실수"를
구분할 방법이 없기 때문이다 — 아래 두 건은 실제로 그 상태로 2개월 가까이 방치되며
ui-audit 이 매 회차 WARN 을 냈다(2026-07-31 조사).

| 앱 | 항목 | 승인된 값 | 사유 |
|---|---|---|---|
| **hub** | 페이지 제목 | `text-[25px] font-bold tracking-tight text-foreground` (반응형 확대 없음) | 승인 시안 `hub/docs/mockups/2026-07-21-hub-preview-v11.html`(`h1 { font-size: 25px; font-weight: 700 }`)대로 구현. 허브는 카드 그리드 위주라 표준 제목(24→30px)이 카드 제목과 층위가 겹쳤다. hub 10개 페이지에 일관 적용. |
| **hub** | 폰트 | 자체 호스팅 `@font-face` → `/fonts/PretendardVariable.woff2` | 외부 CDN 요청 제거. 버전 대조가 성립하지 않으므로 ui-audit 이 **바이트+sha256** 으로 자산 자체를 고정한다(`ui-audit.config.mjs` `selfHostedFont`). |
| **popo-studio** | 페이지 제목 | **없음**(구조적) | 스튜디오형 앱이라 페이지 제목 블록을 두지 않는다. 현재 위치는 헤더 활성 탭이 알린다. `<h1>` 3개는 전부 로그인·승인대기·업로드 화면의 화면명이지 페이지 제목이 아니다. |
| **hub** | §3 로그인 — 바깥 컨테이너·푸터 | 바깥 = `flex flex-1 flex-col items-center justify-center bg-bg-ivory p-6`(`<div>`, `min-h-screen` 없음) · 푸터 = **없음**(`SiteFooter` 담당) | hub 로그인은 `(bare)` 레이아웃의 `<main>` 안에서 렌더되므로 자기가 `<main>`·`min-h-screen` 을 다시 만들지 않고 `flex-1` 로 채운다. CX부 크레딧도 레이아웃의 `SiteFooter` 가 이미 그린다. 제목·폼 카드는 §3 그대로 적용. |

> **예외의 이력화**: hub 제목 예외는 표준을 바꾸자는 뜻이 아니다. hub 가 표준으로 돌아오려면
> 시안부터 다시 그려야 하므로, 그때까지 **여기 적힌 값이 hub 의 기준**이고 ui-audit 은 그 값으로
> hub 를 검사한다(면제가 아니라 **다른 값으로 강제**). popo 만 검사 면제이며, 이는
> "제목을 새로 달 때 아무도 안 본다"는 공백을 동반한다 — 제목을 도입하면 이 표를 먼저 고칠 것.

## 9. 변경 이력

- **v1.20 (2026-08-24)**: **경고 톤의 인자를 다시 세웠다 — "얼마를 치르나"가 아니라 "어디로 가고
  무엇이 사라지나".** S7 이행 결과를 실물로 보고 사용자가 제기한 문제: 생성은 업무를 앞으로
  나아가게 하는 행위인데 유료라는 이유로 경고색이 되는 것이 맞느냐. 진단 = 색 하나에 **행동의
  방향**과 **행동의 대가** 두 의미를 겹쳐 실었다. 정정: **비가역 3분류**(얻는 비가역=확정 ·
  잃는 비가역=경고/파괴 · 밖으로 나감=경고)를 신설하고, **`money`·`bulk` 를 톤 인자에서 제외**해
  각각 **비용 표시 의무**·**확인 게이트 의무**로 옮겼다. 특정 앱 예외가 아니라 인자의 재정의다 —
  같은 기준이 sns AI 초안에도 적용된다. 함께: **`authz` 를 "남의 권한·접근 상태를 결정하는 행동"
  으로 확장**(거부·반려·사용 차단 포함 — money 를 뺀 뒤 거부가 어느 인자에도 안 걸려 확정으로
